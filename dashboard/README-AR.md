# لوحة Final + Final-3 + Phoenix

لوحة محلية على `http://127.0.0.1:8787` لتشغيل ثلاث محاكاة ورقية مستقلة ومقارنة نتائجها.

## بدء جديد: 100 لكل بوت

أوقف أي لوحة قديمة بـ **Ctrl+C** وانتظر انتهاء عملياتها. من داخل مجلد `Final-phoennix`:

```bash
git pull --ff-only
bash run_dashboard.sh --fresh
```

ينشئ `--fresh` مجلد جلسة جديدًا تحت `.runtime/sessions/`، وثلاثة ملفات حالة مستقلة: `final.state.json` و`final3.state.json` و`phoenix.state.json`. تبدأ الحسابات الثلاثة برصيد 100 USDT وصفر مراكز وصفر تنفيذات؛ الإجمالي 300 USDT. لا تُحمّل أرصدة أو صفقات الجلسة السابقة، ولا تُحذف ملفاتها.

السكربت يتطلب Python 3.11+ وGit وبيئة `venv`؛ على الهاتف استخدم بيئة Ubuntu المعتادة. يجهّز `.venv-dashboard` ويثبّت حزم اللوحة. يجلب Final وFinal-3 من مستودعيهما على الفرع `main`، أو يحدّث نسخًا محلية موجودة دون استبدال تعديلات محلية عليها. إذا وجد تعديلات محلية يوقف التجهيز لحمايتها.

إذا ظهر أن المنفذ 8787 مشغول، ارجع إلى الجلسة التي تشغّل اللوحة السابقة وأوقفها بـ Ctrl+C قبل إعادة المحاولة.

## الاستئناف والإيقاف

لاستئناف الحسابات نفسها دون تصفير:

```bash
bash run_dashboard.sh
```

يُحفظ اختيار الجلسة في `.runtime/dashboard-accounts.json`. لا تضف `--fresh` للاستئناف.

يمكن إيقاف كل بوت أو تشغيله من اللوحة، أو إيقاف الثلاثة مع حفظ حالتهم. **Ctrl+C** في الطرفية يوقف الخادم والبوتات الثلاثة. الإيقاف يحفظ المراكز المفتوحة ولا يغلقها؛ تتوقف مراقبتها حتى الاستئناف. لا تشغّل لوحة ثانية على الحسابات نفسها.

## البوتات والسلوك

| البوت | المصدر | آلية المتابعة |

تعرض اللوحة الإعدادات الفعلية ونسخة المصدر لكل بوت. تعرض حالة بيانات Phoenix عدّادات الجولة الحالية، وموعد الفحص التالي بعد الاستراحة القصيرة، وموعد تحديث قائمة العملات بشكل منفصل. البحث يستمر بين تحديثات القائمة؛ زمن الجولة يتأثر بسرعة الشبكة وحدود CCXT، ولا يعني ذلك تحديث كل عملة كل ثانيتين. Phoenix بلا تعزيز، مع انسحاب نصف الكمية عند انعكاس 2.5%، وانتقام معاكس ووضع نجاة حسب شروطه. شروط إشارات Phoenix وإدارة مخاطره ثابتة، والمحدّث هو تكرار البحث بدل الانتظار الطويل. لم تُعدَّل مستودعات Final وFinal-3.

## ما تعرضه اللوحة

- الرصيد وequity والمتاح والهامش وصافي الصفقات المغلقة لكل بوت والإجمالي.
- المراكز المفتوحة وأسعارها ووقفها وحالة التريل والانسحاب أو التعزيز.
- جميع التنفيذات والصفقات المغلقة، مع تجميع الإغلاقات الجزئية والرسوم في صافي الصفقة.
- نتائج مسح Phoenix، بما فيها عدد العملات المفحوصة ونتائج الشروط وأخطاء الفحص ومحاولات الدخول، حتى قبل أول صفقة.
- حالة البيانات وسجل التشغيل، والنجاة والانتقام المعلّق في إعدادات Phoenix.

تتحدث اللوحة كل 3 ثوانٍ. تحديث لقطة اللوحة لا يثبت حداثة السوق: تعرض Final وFinal-3 عمر أحداث WebSocket، وتعرض Phoenix نتائج المسح وتيكرات REST المرصودة. عند غياب طابع التيكر الزمني لا تصفه اللوحة بأنه حديث مثبت، رغم أن استراتيجية Phoenix تقبل السعر وفق سلوكها المعتمد.

## تصدير الصفقات

من **سجل الصفقات** اختر البوت أو «الكل»، ثم نزّل:

- **الصفقات CSV:** الصفقات المغلقة، بصافي يشمل الرسوم والإغلاقات الجزئية.
- **التنفيذات CSV:** كل دخول وتعزيز وإغلاق جزئي وكامل.
- **تقرير الثلاثة JSON:** حالة الحسابات والإعدادات والتنفيذات والسجل المتاح.

أرشيف SQLite مستقل لكل حساب يحفظ التنفيذات المتاحة والجديدة خارج حد 150 تنفيذًا في حالة Phoenix. لا يمكن استرجاع تنفيذات حُذفت قبل استيرادها إلى اللوحة. السجلات التي ينقصها الدخول تُعلّم بأنها ناقصة ولا تُحسب ضمن إحصاءات الصفقات المكتملة.

إذا أوقفت البوتات من أزرار اللوحة، يظل الخادم متاحًا لتنزيل التقارير. إذا أغلقت الخادم بـ Ctrl+C، يمكنك فتحه دون تشغيل البوتات لتنزيل التقارير:

```bash
bash run_dashboard.sh --no-autostart
```

لا تستخدم `--fresh` عند استخراج تقرير الجلسة التي أوقفتها.


تستخدم الاختبارات بيانات وهمية؛ لا تختبر اتصال هاتفك الفعلي ببيانات Binance. المحاكاة لا تنفّذ أوامر تداول حقيقية.

تحديث Final-3: كل أصلية ومعاكسة تُحسب مركزًا مستقلًا ضمن حد5؛ ملفات المراكز القديمة بنظام التعزيز لا تُحوّل تلقائيًا. استخدم `--fresh` لحسابات جديدة إذا كانت الجلسة القديمة ما زالت تحمل مراكز من نظام7%.

تحديث النسخة الحالية من Final-3: أصبح المدخل الافتراضي نظام وقف2.8% وجزئيات40% ثم50% من المتبقي. نسخة الانعكاس3% محفوظة للتشغيل المستقل في `cascade_final3_reversal.py` بملف حالة مستقل. راجع README في Final-3 لقيود أولوية الوقف وشروط القفل المرسلة، ولا تستأنف مراكز نسخة أخرى بمدخل الاستراتيجية الجديدة.
