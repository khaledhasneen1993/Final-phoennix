# Final Phoenix v2

محاكاة مستقلة بملف تشغيل واحد `final_phoenix.py`. الملف هو كود v2 الذي قدّمه صاحب المشروع كما أُرسل، دون تغييرات إضافية على منطقه. لا تعدّل هذه النسخة البوتات الثلاثة السابقة ولا تضيف نفسها إلى لوحتها.

## التشغيل

يتطلب Python 3.11 أو أحدث واتصالاً ببيانات Binance العامة. الحساب ورقي ولا يحتاج مفاتيح تداول.

```bash
cd /root
git clone https://github.com/khaledhasneen1993/Final-phoennix.git
cd Final-phoennix
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final_phoenix.py
```

لتحديث نسخة موجودة، أوقف العملية أولاً ثم نفّذ داخل مجلدها:

```bash
git pull --ff-only
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final_phoenix.py
```

الحساب الجديد يبدأ بـ100 USDT. التشغيل يستأنف `paper_state_phoenix.json` إن وُجد في مجلد العمل ولا يعيد ضبط الرصيد. الإيقاف يلغي المهام الخلفية ويحفظ الحالة ويغلق عميل الشبكة عبر `finally` في الظروف العادية. الإيقاف القسري لا يضمن تنفيذ التنظيف.

## سلوك v2

- رافعة حسابية 50×، أربعة مراكز بحد أقصى، بلا تعزيز. شروط الإشارة: حركة تتجاوز 1.2%، حجم أكبر من 3.5 أضعاف المتوسط، واختلال دفتر أوامر يتجاوز ±0.35.
- وقف أولي 5.5%، وانسحاب بإغلاق نصف الكمية عند انعكاس 2.5%. بعد الانسحاب يصبح الوقف على مسافة 3.2% **من سعر تنفيذ الانسحاب**، وليس من متوسط الدخول رغم التعليق داخل المصدر. مثال شراء عند100 ثم انسحاب عند97.5: الوقف الجديد94.38، أدنى من الوقف الأول94.5 قليلاً؛ لا يضمن الكود تشديد الوقف القديم دائماً. لا يغلق الباقي لمجرد بقاء السعر عند سعر الانسحاب.
- ربح1.8% يفعّل تريل0.9% يتحرك باتجاه الربح فقط، ويسجل خروجه `TRAIL_SL`.
- الهامش9% حتى قوة0.11، ثم `min(0.15, 0.09 + (strength - 0.11) * 0.8)`؛ يبلغ15% عند قوة0.185. هامش الانتقام5.85% من الرصيد (65% من الهامش الأساسي)، ويأخذ وضع النجاة الأولوية بهامش2.7%.
- النجاة تبدأ تحت85% من أعلى رصيد وتنتهي فوق93%.
- خسارة الإغلاق الكامل قبل الرسوم الأكبر من8 USDT تجهّز انتقاماً في الاتجاه المعاكس، ويتطلب إشارة توافق الاتجاه. القرار لا يجمع نتائج الإغلاقات الجزئية أو رسوم الدخول ضمن خسارة الصفقة.
- الحظر45دقيقة مبني على آخر خسارتين كبيرتين سجلتهما دالة الإغلاق الكامل؛ الأرباح لا تصفّر هذا التسلسل.
- أعلى40عملة تُفحص بالتتابع ثم ينتظر البوت600ثانية. لا يوجد مسح دخول مستمر أو انحياز5دقائق. مراقبة الخروج مستقلة مع انتظار7ثوانٍ بين الدورات بالإضافة لزمن الشبكة، والحالة تُطبع كل25ثانية.
- الحفظ يستخدم ملفاً مؤقتاً ثم استبدالاً، ويشمل رصيد القمة والمراكز والحظر وذاكرة الخسائر وجاهزية الانتقام واتجاهه وحالة النجاة. تُحفظ آخر150عملية تنفيذ فقط؛ ملف الحالة ليس أرشيفاً كاملاً. الملفات السابقة تُحمّل مع قيم افتراضية للحقول الجديدة. أسعار التقييم اللحظية لا تُستعاد من الحالة.

## نقاط باقية في المصدر المقدم

- `MAX_TICKER_AGE = 12.0` غير مستخدم. `fresh_ticker` يجلب تيكراً جديداً ويتحقق أن السعر موجب، لكنه لا يفحص الطابع الزمني؛ لذلك لا يرفض بالضرورة سعراً عمره أكثر من12ثانية.
- `detect` يرفض العملة المحظورة قبل تقييم إشارتها، وبالتالي يمنع أيضاً اكتشاف إشارة الانتقام عليها، رغم السماح بتجاوز الحظر داخل `enter` للانتقام.
- `try_revenge` يمسح الجاهزية بعد أول فحص حتى دون وجود إشارة مناسبة أو عند فشل الدخول. الانتقام ليس أمراً مضمون التنفيذ.
- الإغلاق الكامل بسعر يمرره المستدعي لا يعيد طلب التيكر؛ المسار المعتاد للإدارة يمرر السعر الذي جلبه للتو.
- لا يوجد منع داخلي لدخول مكرر على العملة داخل `enter` أو الحساب الورقي؛ المسار العادي للمسح يستبعد العملات ذات المراكز بالفعل.
- عند إغلاق كمية أكبر من المركز، تُحتسب رسوم الحساب من الكمية المطلوبة قبل حصر الكمية المنفذة. مسارات الاستراتيجية المعتادة تطلب نصف الكمية أو كاملها فقط.
- التنظيف لا ينتظر انتهاء المهام الملغاة صراحةً، وفشل حفظ الحالة في `finally` قد يمنع الوصول إلى إغلاق عميل الشبكة.

هذه قيود موثّقة للمطابقة مع النص المرسل، ولم تُعدّل تلقائياً.
