# Final Phoenix v2

بوت محاكاة مستقل بملف تشغيل واحد: `final_phoenix.py`. يستخدم بيانات Binance USDⓈ-M العامة وينفّذ الأوامر داخل حساب ورقي يبدأ بـ **100 USDT** عند عدم وجود حالة محفوظة. لا يحتاج مفاتيح API.

## تشغيل Final + Final-3 + Phoenix مع لوحة التحكم

أوقف اللوحة القديمة بـ **Ctrl+C** أولًا، ثم من داخل مجلد هذا الريبو:

```bash
git pull --ff-only
bash run_dashboard.sh --fresh
```

افتح **http://127.0.0.1:8787** على الجهاز نفسه. ينشئ `--fresh` جلسة جديدة بحسابات مستقلة، **100 USDT وصفر صفقات لكل بوت** (300 USDT إجمالًا)، ويحافظ على الجلسات القديمة. يحمّل السكربت Final وFinal-3 من مستودعيهما ويشغّل Phoenix الحالي من هذا الريبو. لا يشغّل My-life ضمن هذه المجموعة.

لاستئناف الجلسة نفسها لاحقًا:

```bash
bash run_dashboard.sh
```

التفاصيل والتصدير في [دليل لوحة التحكم](dashboard/README-AR.md).

## تشغيل Phoenix منفردة

يتطلب Python 3.11 أو أحدث. داخل Linux أو Ubuntu على الهاتف:

```bash
git clone https://github.com/khaledhasneen1993/Final-phoennix.git
cd Final-phoennix
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final_phoenix.py
```

لتحديث نسخة موجودة: أوقف البوت بـ **Ctrl+C**، ثم نفّذ داخل مجلد المشروع:

```bash
git pull --ff-only
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final_phoenix.py
```

التشغيل يستأنف الحالة المحفوظة؛ لا يعيد الرصيد تلقائيًا إلى 100.

## الإشارات والحجم

تعتمد الإشارة على شموع الدقيقة ودفتر الأوامر:

- شراء: حركة أكبر من +1.2%، وحجم أكبر من 3.5 أضعاف المتوسط، واختلال دفتر أوامر أكبر من +0.35.
- بيع: حركة أقل من −1.2%، وحجم أكبر من 3.5 أضعاف المتوسط، واختلال دفتر أوامر أقل من −0.35.
- القوة: `abs(ret) * vol_spike * abs(imb)`.

تُرتّب الإشارات حسب القوة. لا يوجد انحياز 5 دقائق في Phoenix. ينتهي المسح ثم ينتظر البوت 600 ثانية؛ **مراقبة الخروج مستقلة وتستمر خلال الانتظار**، لكن اكتشاف الدخول ليس مستمرًا خلاله.

الهامش العادي:

```python
margin_pct = 0.09 if strength <= 0.11 else min(
    0.15, 0.09 + (strength - 0.11) * 0.8
)
```

يبلغ 15% عند قوة 0.185 أو أكثر. الانتقام يستخدم 65% من الهامش الأساسي، ووضع النجاة له الأولوية بهامش 2.7%. يُرفض الدخول عند عدم كفاية المتاح للهامش والرسوم، أو وجود مركز على العملة نفسها؛ لا يوجد تعزيز.

## إدارة الخروج

1. يبدأ المركز بوقف 5.5% من الدخول.
2. عند انعكاس 2.5% يُغلق نصف الكمية مرة واحدة.
3. يُضبط وقف الباقي على مسافة 3.2% من **سعر تنفيذ الانسحاب**، أسفله للشراء وأعلاه للبيع. لا يُغلق الباقي لمجرد بقاء السعر عند سعر الانسحاب.
4. ربح 1.8% يفعّل التريل بمسافة 0.9%، مع تحديث أفضل سعر وتحريك الوقف باتجاه الربح فقط.

مثال شراء عند 100 وانسحاب عند 97.5: وقف الباقي = `97.5 × 0.968 = 94.38`. هذه المعادلة قد تجعل وقف Retreat أبعد قليلًا من الوقف الأول؛ لا يفرض الكود تشديده مقارنةً بالوقف السابق.

أسباب الخروج: `SMART_RETREAT` و`SL` و`TRAIL_SL`. رسوم الإغلاق تُحسب على الكمية المنفذة فعلًا، وتبقى كمية الاستراتيجية مطابقة لكمية الحساب بعد الإغلاق الجزئي.

## الانتقام والحظر والنجاة

**الانتقام:** خسارة أكبر من 8 USDT في تنفيذ إغلاق كامل تجهّز دخولًا على العملة نفسها بالاتجاه المعاكس، بشرط وجود إشارة توافقه. يمكن للانتقام اكتشاف العملة المحظورة والدخول عليها، بينما يظل الدخول العادي خاضعًا للحظر.

تبقى جاهزية الانتقام محفوظة عند غياب الإشارة أو فشل الدخول، وتُمسح فقط بعد نجاحه. تُجرى محاولاته ضمن دورة المسح مع تطبيق مهلة الدخول وحد المراكز وفحص السعر والهامش ومنع تكرار المركز. توجد خانة واحدة لانتقام معلّق؛ خسارة مؤهلة لاحقة تستبدل بياناته.

قرار الانتقام يعتمد على خسارة تنفيذ الإغلاق الكامل قبل الرسوم، ولا يجمع نتائج الإغلاقات الجزئية أو رسوم الدخول.

**الحظر:** لمدة 45 دقيقة عندما يكون مجموع آخر خسارتين مسجلتين في ذاكرة الخسائر أقل من −10 USDT. تُحدَّث هذه الذاكرة للخسائر الكبيرة المذكورة فقط؛ الأرباح لا تصفّرها.

**النجاة:** تتفعّل عندما ينخفض الرصيد إلى أقل من 85% من أعلى رصيد مسجل، وتنتهي فوق 93%. تعتمد على الرصيد المحقق، لا على equity المتغير مع المراكز المفتوحة.

## حداثة السعر

يجلب `fresh_ticker` التيكر ويتحقق من سعر موجب ومحدود. إذا احتوى على `timestamp` غير صفري، يُرفض عندما يتجاوز عمره 12 ثانية؛ عند غياب الطابع الزمني أو كونه `None` أو صفرًا يُقبل السعر دون تقدير عمره.

يُستخدم الفحص قبل الدخول والإغلاق الجزئي وفحص المراكز. الإغلاق الكامل يستخدم السعر الممرر إليه من إدارة المراكز بعد فحصه، أو يطلب تيكرًا ويفحصه إذا لم يُمرَّر سعر.

## حفظ الحالة والإيقاف

ملف الحالة `paper_state_phoenix.json` داخل مجلد التشغيل. يحفظ الرصيد والقمة والمراكز والوقف والتريل وحالة الانسحاب والحظر وذاكرة الخسائر وجاهزية الانتقام واتجاهه وحالة النجاة وآخر أوقات الدخول، إضافة إلى **آخر 150 عملية تنفيذ**.

الحفظ عبر ملف مؤقت ثم استبدال الملف الأساسي. تُحمّل الحقول الجديدة بقيم افتراضية عند استئناف ملف قديم. عند تعذر قراءة الحالة يتوقف بدء التشغيل للحفاظ على الملف الأصلي؛ لا يبدأ حسابًا بديلًا فوقه. أسعار التقييم اللحظية تُجلب مجددًا بعد الاستئناف.

اضغط **Ctrl+C** مرة واحدة وانتظر انتهاء العملية. ينتظر البوت إنهاء المهام الملغاة ثم يحفظ الحالة ويحاول إغلاق الاتصال حتى لو فشل الحفظ. الإيقاف القسري لا يضمن آخر حفظ.

الإيقاف يحفظ المراكز الورقية ولا يغلقها؛ تتوقف مراقبتها حتى تشغيل البوت مجددًا. ملف الحالة ليس تقريرًا تاريخيًا كاملًا: الدخول والإغلاق الجزئي والكامل عمليات منفصلة ضمن حد 150.
