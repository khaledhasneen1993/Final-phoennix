# Final Phoenix v2

بوت محاكاة تداول بملف تشغيل واحد: `final_phoenix.py`، باستخدام بيانات Binance USDⓈ-M العامة. يبدأ الحساب الجديد برصيد **100 USDT**، وتُنفَّذ جميع الأوامر داخل الحساب الورقي.

هذه النسخة تعتمد كود Phoenix v2 المرسل للمشروع. يوضح هذا الدليل الإعدادات والسلوك الفعلي للكود، بما في ذلك الإصلاحات المنفذة والنقاط التي ما زالت تحتاج تعديلًا.

## المتطلبات

- Python 3.11 أو أحدث.
- اتصال بالإنترنت للوصول إلى بيانات Binance.
- الحزم الموجودة في `requirements.txt`.
- لا يلزم إدخال مفاتيح API للمحاكاة.

## التثبيت والتشغيل

داخل بيئة Linux، أو Ubuntu المستخدمة على الهاتف:

```bash
git clone https://github.com/khaledhasneen1993/Final-phoennix.git
cd Final-phoennix
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final_phoenix.py
```

اسم المستودع على GitHub هو **Final-phoennix**، واسم ملف التشغيل هو **final_phoenix.py**.

لتحديث نسخة مثبتة، أوقف البوت بـ **Ctrl+C** ثم نفّذ من داخل مجلد المشروع:

```bash
git pull --ff-only
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final_phoenix.py
```

التشغيل يستأنف الحساب المحفوظ إن وُجد؛ التحديث لا يعيد الرصيد تلقائيًا إلى 100.

## اكتشاف الإشارات

يفحص البوت أعلى العملات المطابقة لحجم التداول، باستخدام شموع الدقيقة ودفتر الأوامر:

- شراء: حركة أكبر من +1.2%، وحجم أكبر من 3.5 أضعاف المتوسط، واختلال دفتر أوامر أكبر من +0.35.
- بيع: حركة أقل من −1.2%، وحجم أكبر من 3.5 أضعاف المتوسط، واختلال دفتر أوامر أقل من −0.35.
- قوة الإشارة: `abs(ret) * vol_spike * abs(imb)`.

تُرتّب الإشارات حسب القوة قبل محاولة الدخول. لا يوجد انحياز 5 دقائق في Phoenix v2. بعد اكتمال المسح ينتظر البوت 600 ثانية؛ مراقبة الخروج تستمر بمهمة مستقلة خلال هذا الانتظار.

## الحجم الديناميكي

للدخول العادي:

```python
margin_pct = 0.09 if strength <= 0.11 else min(
    0.15, 0.09 + (strength - 0.11) * 0.8
)
```

يصل الهامش إلى 15% عند قوة إشارة 0.185 أو أكثر. حجم الانتقام هو 5.85% من الرصيد، ويأخذ وضع النجاة الأولوية على كلا الحجمين بهامش 2.7%. تُرفض محاولة الدخول إذا لم يكفِ المتاح للهامش والرسوم.

## Smart Retreat والوقف والتريل

لا يوجد تعزيز أو مضاعفة لمركز خاسر.

1. يبدأ المركز بوقف على مسافة 5.5% من سعر الدخول.
2. عند انعكاس 2.5% يُغلق نصف الكمية مرة واحدة.
3. يُضبط وقف الباقي على مسافة 3.2% من **سعر تنفيذ الانسحاب**: أسفل السعر للشراء، وأعلاه للبيع. لذلك لا يُغلق الباقي لمجرد بقاء السعر عند مستوى الانسحاب.
4. عند ربح 1.8% يتفعّل التريل، وتُحدّث أفضل قيمة للسعر، ويتحرك الوقف باتجاه الربح فقط بمسافة 0.9%.

مثال شراء عند 100 وانسحاب عند 97.5: الوقف الجديد `97.5 × 0.968 = 94.38`. المرجع هو سعر الانسحاب رغم أن التعليق داخل المصدر يذكر المتوسط. وقد يكون الوقف الجديد أبعد قليلًا من الوقف الأول؛ الكود لا يفرض تشديده مقارنةً بالوقف السابق عند Retreat.

أسباب الخروج المسجلة هي `SMART_RETREAT` و`SL` و`TRAIL_SL`.

## Revenge Mode والحظر

خسارة **أكبر من 8 USDT** في تنفيذ إغلاق كامل تجهّز انتقامًا على العملة نفسها بعكس اتجاه المركز المغلق. يتطلب الدخول إشارة توافق الاتجاه المعاكس، ويستخدم حجم الانتقام المحدد أعلاه.

حساب هذه الخسارة يعتمد على ربح/خسارة تنفيذ الإغلاق الكامل قبل الرسوم، ولا يجمع نتائج الإغلاق الجزئي أو رسوم الدخول.

يُفرض حظر لمدة 45 دقيقة عندما يكون مجموع آخر خسارتين مسجلتين في ذاكرة الخسائر أقل من −10 USDT. هذه الذاكرة تُحدَّث للخسائر الكبيرة المذكورة فقط، ولا تُصفَّر بعد صفقة رابحة.

**قيود التنفيذ الحالية:**

- دالة اكتشاف الإشارات ترفض العملة المحظورة، مما يمنع اكتشاف إشارة الانتقام عليها أيضًا، رغم السماح بتجاوز الحظر داخل دالة دخول الانتقام.
- تُمسح جاهزية الانتقام بعد أول فحص، حتى دون إشارة مناسبة أو إذا فشل الدخول. لا تبقى جاهزة حتى نجاح التنفيذ.

## Survival Mode

- يتفعّل عندما ينخفض الرصيد إلى أقل من 85% من أعلى رصيد مسجل.
- يخفّض هامش الدخول إلى 2.7% من الرصيد.
- يتوقف عندما يعود الرصيد إلى أكثر من 93% من القمة.
- يعتمد على الرصيد المحقق، وليس على equity المتغير مع المراكز المفتوحة.

## حداثة السعر

يجلب `fresh_ticker` سعرًا عبر طلب تيكر قبل الدخول والإغلاق الجزئي وفحص المراكز، ويتحقق أن السعر موجب.

**فحص العمر الزمني غير مكتمل:** الثابت `MAX_TICKER_AGE = 12.0` معرّف، لكن الكود لا يقارن الطابع الزمني للتيكر بالوقت الحالي. لذلك لا يمكن اعتبار رفض الأسعار الأقدم من 12 ثانية ميزة منفذة في هذه النسخة. الإغلاق الكامل يستخدم السعر الممرر إليه، أو يجلب تيكرًا إن لم يُمرَّر سعر.

## حفظ الحالة واستئنافها

ملف الحالة: `paper_state_phoenix.json` داخل مجلد التشغيل.

يحفظ البوت:

- الرصيد، أعلى رصيد، equity، الهامش المستخدم والمتاح.
- مراكز الحساب ومراكز الاستراتيجية، بما فيها الوقف والتريل وحالة الانسحاب.
- آخر أوقات الدخول والحظر وذاكرة الخسائر.
- جاهزية الانتقام وعملته واتجاهه، وحالة النجاة.
- آخر **150 عملية تنفيذ** وتوقيت التحديث.

تُكتب الحالة إلى ملف مؤقت ثم يُستبدل به الملف الأساسي. تُحمّل ملفات الحالة القديمة مع قيم افتراضية للحقول الجديدة؛ لا يمكن استرجاع ذاكرة لم تكن محفوظة أصلًا. أسعار التقييم اللحظية لا تُستعاد إلى ذاكرة الأسعار، بل تُحدَّث عند جلب بيانات جديدة.

آخر 150 عملية تنفيذ ليست أرشيفًا كاملًا لجميع الصفقات؛ الدخول والإغلاق الجزئي والإغلاق الكامل عمليات منفصلة.

## الإيقاف

اضغط **Ctrl+C** مرة واحدة واترك العملية تنتهي. ينفّذ مسار `finally` إلغاء المهام الخلفية وحفظ الحالة وإغلاق عميل البورصة في الظروف العادية، مع بقاء المراكز الورقية محفوظة للاستئناف.

الإيقاف لا يغلق المراكز تلقائيًا، وتتوقف مراقبة الوقف والتريل حتى تشغيل البوت مجددًا. الإيقاف القسري لا يضمن الحفظ الأخير. كذلك لا ينتظر الكود المهام الملغاة صراحةً، وقد يمنع فشل الحفظ الوصول إلى إغلاق عميل الشبكة.
