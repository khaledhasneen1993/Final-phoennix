# Final Phoenix

نسخة مستقلة للمحاكاة فقط، بملف تشغيل واحد `final_phoenix.py`. نُقل كود الاستراتيجية كما قدّمه صاحب المشروع دون تغيير منطقه. لا تتضمن هذه النسخة لوحة البوتات الثلاثة ولا تعدّل مستودعاتها.

## التشغيل

يتطلب Python 3.11 أو أحدث واتصالاً بواجهات بيانات Binance العامة. لا يحتاج مفاتيح تداول؛ الأوامر تُنفّذ داخل الحساب الورقي فقط.

```bash
cd /root
git clone https://github.com/khaledhasneen1993/Final-phoennix.git
cd Final-phoennix
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -u final_phoenix.py
```

يبدأ الحساب الجديد برصيد 100 USDT. يُحمّل ملف `paper_state_phoenix.json` الموجود في مجلد التشغيل إن وُجد؛ التشغيل العادي يستأنف الحساب ولا يعيد ضبطه. الملف يحتوي آخر 120 عملية تنفيذ فقط، وليس أرشيفاً كاملاً لجميع الصفقات.

## السلوك الفعلي للكود المقدم

- رافعة حسابية 50×، أربعة مراكز بحد أقصى، ولا يوجد تعزيز.
- الوقف الأولي 5.5% من سعر الدخول. عند خسارة سعرية 2.5% تُغلق نصف الكمية، ثم يُضبط وقف الباقي عند خسارة 1.2% من الدخول. هذا الوقف يكون قد تجاوز السعر الحالي عادةً؛ إذا بقي السعر عند مستوى الانسحاب تُغلق الكمية الباقية في فحص الإدارة التالي.
- ربح سعري 1.8% يفعّل التريل بمسافة 0.9%. الوقف المتحرك يتحرك باتجاه الربح فقط. سبب إغلاقه في السجل يبقى `SL` وفق المصدر المقدم.
- الهامش الأساسي 9%، وعند قوة إشارة أكبر من 0.12 يصبح 13.95% بالمعادلة الحالية؛ ثابت الحد الأعلى 15% لا يعني أن الحجم يصل إليه فعلياً.
- وضع النجاة يبدأ تحت 85% من أعلى رصيد مسجل، ويستخدم هامش 3.15%، وينتهي فوق 93%.
- تُفحص قائمة أعلى 40 عملة بالتتابع، ثم ينتظر البوت 600 ثانية بعد اكتمال الدورة. لا يوجد فحص دخول مستمر أثناء الانتظار، ولا انحياز 5 دقائق في هذه النسخة.
- مراقبة الخروج مهمة مستقلة، وبين دوراتها انتظار 7 ثوانٍ بالإضافة إلى مدة طلبات الشبكة. الحالة تُطبع كل 25 ثانية.
- ثابت `REVENGE_SIZE_MULT = 0.7` معرّف لكنه غير مستخدم في حساب الكمية. وضع الانتقام يقلل قوة الإشارة المدخلة إلى دالة الحجم، ولا يضمن تصغير الكمية إلى 70% أو عكس اتجاه الخسارة. تُمسح جاهزيته بعد محاولة الدخول حتى إن فشلت.
- الانتقام والحظر يتأثران بخسارة إجمالية قبل الرسوم أكبر من 8 USDT في الإغلاق الكامل وحده. الحظر يفحص آخر خسارتين مسجلتين بهذه الطريقة، ولا يعيد ضبط التسلسل بعد الأرباح، ولا يجمع خسائر الإغلاق الجزئي ضمن حساب خسارة الصفقة.
- لا يوجد فحص لعمر التيكر قبل الأوامر. أخطاء اكتشاف الإشارات تعيد `None` دون تسجيل تفاصيل الخطأ.
- ملف الحالة لا يحفظ جاهزية الانتقام أو سجل الخسائر أو حالة النجاة. ولا يتضمن المصدر معالجة نهائية مضمونة لحفظ الحالة وإغلاق عميل الشبكة عند Ctrl+C؛ يحتفظ بما تم حفظه خلال التنفيذ.

هذه الملاحظات توثّق المصدر المعتمد كما أُرسل، ولا تضيف تعديلات إلى الاستراتيجية.
